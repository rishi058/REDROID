# DiskWala 26.1 on x86_64 ReDroid

This document records the verified local WSL/ReDroid procedure and the failed approaches so the same state can be reproduced in another ReDroid container.

> **Later verified resolution:** read [DW_26_1_part2.md](DW_26_1_part2.md) before repeating these experiments. Adding `com.diskwalaapp!` to the existing TrickyStore targets produced genuine `attest/verify` HTTP 200 (`ok=true`, `tier=full`). A separate factory/update GMS permission mismatch was repaired, and Home plus successful token refresh were verified with no response mocks or UI override. The Strong-Integrity-only blocker theory below is historical, not the final diagnosis.

## 1. Final tested state

Environment:

- Host: WSL2 on x86_64
- ReDroid image: `redroid/redroid:14.0.0-latest`
- Android: 14 / API 34
- Container architecture: `linux/amd64`
- Application: `com.diskwalaapp`
- DiskWala version: `26.1` (`versionCode=352`)
- DiskWala native ABI: `arm64-v8a`
- ARM translation: built-in `libndk_translation`

Final package state:

```text
codePath=/system/app/DiskWala
primaryCpuAbi=arm64-v8a
flags=[ SYSTEM HAS_CODE ALLOW_CLEAR_USER_DATA ]
installerPackageName=com.android.vending
initiatingPackageName=com.android.vending
packageSource=1
```

Final independent Play Integrity result:

```text
appRecognitionVerdict=PLAY_RECOGNIZED
deviceRecognitionVerdict=[MEETS_BASIC_INTEGRITY, MEETS_DEVICE_INTEGRITY]
appLicensingVerdict=LICENSED
playProtectVerdict=NO_ISSUES
appAccessRiskVerdict.appsDetected=[KNOWN_INSTALLED]
```

`UNKNOWN_INSTALLED` was removed successfully.

DiskWala still displays:

```text
This device isn't supported
DiskWala needs a device that can prove it hasn't been modified.
```

The remaining blocker is therefore not BASIC integrity, DEVICE integrity, installer metadata, or `UNKNOWN_INSTALLED`. The strongest remaining difference is the absence of `MEETS_STRONG_INTEGRITY` and the x86 ReDroid platform's missing hardware-backed StrongBox/RKP implementation.

## 5. Why `HARDWARE_TYPE_UNAVAILABLE` remains

The live image exposes Keymaster 4.1:

```text
android.hardware.keymaster@4.1::IKeymasterDevice/default
```

It does not expose a working StrongBox or remotely provisioned KeyMint component. The remote-provisioning service therefore logs:

```text
HARDWARE_TYPE_UNAVAILABLE
```

Useful checks:

```powershell
adb -s 127.0.0.1:5555 shell service list | findstr /I "keymint keymaster remotelyprovisioned rkpd registration strongbox"
adb -s 127.0.0.1:5555 shell su -c "lshal" | findstr /I "keymaster keymint remotelyprovisioned secureclock sharedsecret"
adb -s 127.0.0.1:5555 shell cmd remote_provisioning list
adb -s 127.0.0.1:5555 shell cmd remote_provisioning dump
```

On this x86 image, `cmd remote_provisioning list` produced no usable component. A keybox can make BASIC and DEVICE pass through TrickyStore, but it does not create a physical StrongBox/TEE or a native x86 certificate-generation implementation.

Disabling a package is insufficient because it remains installed. The tested instance stopped returning `UNKNOWN_INSTALLED` only after uninstalling these user packages:

The app is ARM64-only while the Play device catalog sees the ReDroid device as x86_64. Advertising ARM support through `libndk_translation` is enough for Package Manager, but it does not make the Play catalog deliver the ARM-only bundle.


```text

initiatingPackageName=com.android.shell
```

## 8. Preloading DiskWala as a system app

A system preload prevents DiskWala itself from contributing to `UNKNOWN_INSTALLED` and lets PairIP's local installer check accept it as a system package.

### 8.1 Determine the persistent data volume

```powershell
wsl.exe -d Ubuntu -u root -- docker volume inspect local-setup_redroid14-data
```

The tested volume was:

```text
local-setup_redroid14-data
```

### 8.2 Create a KernelSU system-overlay module

Verify the parents first:

```powershell
adb -s 127.0.0.1:5555 shell su -c "test -d /data/adb/modules && echo modules-parent-ok"
```

If Android `su` is unavailable, Docker root can write the persistent `/data` volume directly.

Create this layout:

```text
/data/adb/modules/diskwala_system/
  module.prop
  system/app/DiskWala/
    base.apk
    split_config.arm64_v8a.apk
    split_config.en.apk
    split_config.xxhdpi.apk
```

`module.prop`:

```ini
id=diskwala_system
name=DiskWala System Preload
version=1
versionCode=1
author=local
description=Preloads the exact Play-signed DiskWala split APK set as a system app
```

Example Docker commands from WSL:

```sh
docker exec redroid14 mkdir -p /data/adb/modules/diskwala_system/system/app/DiskWala

docker cp /mnt/d/PROJECT/_TRASH/REDROID/rev-eng/apk-extractor/target-apk/DiskWala_26_1_extracted/base.apk \
  redroid14:/data/adb/modules/diskwala_system/system/app/DiskWala/base.apk

docker cp /mnt/d/PROJECT/_TRASH/REDROID/rev-eng/apk-extractor/target-apk/DiskWala_26_1_extracted/split_config.arm64_v8a.apk \
  redroid14:/data/adb/modules/diskwala_system/system/app/DiskWala/split_config.arm64_v8a.apk

docker cp /mnt/d/PROJECT/_TRASH/REDROID/rev-eng/apk-extractor/target-apk/DiskWala_26_1_extracted/split_config.en.apk \
  redroid14:/data/adb/modules/diskwala_system/system/app/DiskWala/split_config.en.apk

docker cp /mnt/d/PROJECT/_TRASH/REDROID/rev-eng/apk-extractor/target-apk/DiskWala_26_1_extracted/split_config.xxhdpi.apk \
  redroid14:/data/adb/modules/diskwala_system/system/app/DiskWala/split_config.xxhdpi.apk
```

Set permissions:

```sh
chmod 0755 /data/adb/modules/diskwala_system
chmod 0755 /data/adb/modules/diskwala_system/system
chmod 0755 /data/adb/modules/diskwala_system/system/app
chmod 0755 /data/adb/modules/diskwala_system/system/app/DiskWala
chmod 0644 /data/adb/modules/diskwala_system/module.prop
chmod 0644 /data/adb/modules/diskwala_system/system/app/DiskWala/*.apk
```

Remove any user/data installation of DiskWala before rebooting:

```powershell
adb -s 127.0.0.1:5555 shell pm uninstall --user 0 com.diskwalaapp
```

On a clean new ReDroid volume, install the overlay before the first Android boot whenever possible. This avoids carrying old sideload install-source state into the system package record.

## 9. Correcting stale install-source state

This section is needed only when the same volume previously contained a shell-installed copy. It is unsupported Package Manager state surgery; keep a backup and perform it only while Android is stopped.

### 9.1 Decode Android Binary XML

Android 14 stores `/data/system/packages.xml` as Android Binary XML (`ABX`). Do not edit the binary file directly.

Copy it to a shell-readable location with Docker root:

```sh
docker exec redroid14 cp /data/system/packages.xml /data/local/tmp/packages.abx
docker exec redroid14 chown 2000:2000 /data/local/tmp/packages.abx
docker exec redroid14 chmod 0644 /data/local/tmp/packages.abx
```

Decode through an Android shell, which has the required ART environment:

```powershell
adb -s 127.0.0.1:5555 shell abx2xml \
  /data/local/tmp/packages.abx \
  /data/local/tmp/packages-decoded.xml

adb -s 127.0.0.1:5555 pull \
  /data/local/tmp/packages-decoded.xml \
  "$env:TEMP\packages-decoded.xml"
```

Do not run `abx2xml` directly through a raw Docker process without Android's boot classpath environment.

### 9.2 Edit only the DiskWala package attributes

Find:

```xml
<package name="com.diskwalaapp" ...>
```

Set or replace only these attributes:

```xml
installer="com.android.vending"
installerUid="<CURRENT_COM_ANDROID_VENDING_UID>"
packageSource="1"
isOrphaned="false"
installInitiator="com.android.vending"
```

Obtain the current Play Store UID rather than copying the tested value:

```powershell
adb -s 127.0.0.1:5555 shell pm list packages -U com.android.vending
```

The tested instance returned UID `10096`, but this can differ in another container.

Do not copy timestamps, user IDs, certificate indices, domain IDs, or the complete tested package line into another ReDroid instance.

### 9.3 Re-encode and verify

```powershell
adb -s 127.0.0.1:5555 push \
  "$env:TEMP\packages-decoded.xml" \
  /data/local/tmp/packages-edited.xml

adb -s 127.0.0.1:5555 shell rm -f /data/local/tmp/packages-edited.abx
adb -s 127.0.0.1:5555 shell xml2abx \
  /data/local/tmp/packages-edited.xml \
  /data/local/tmp/packages-edited.abx
```

The encoded file must begin with the `ABX` magic bytes. Verify through Docker root:

```sh
xxd -l 16 /data/local/tmp/packages-edited.abx
```

Expected prefix:

```text
4142 5800
```

### 9.4 Replace the state offline

Stop ReDroid before touching the live Package Manager file:

```powershell
wsl.exe -d Ubuntu -u root -- docker stop -t 30 redroid14
```

Locate the Docker volume mountpoint:

```powershell
wsl.exe -d Ubuntu -u root -- docker volume inspect local-setup_redroid14-data
```

For the tested volume, the host path was:

```text
/var/lib/docker/volumes/local-setup_redroid14-data/_data
```

Create a backup and install the edited ABX file:

```sh
cp /var/lib/docker/volumes/local-setup_redroid14-data/_data/system/packages.xml \
   /var/lib/docker/volumes/local-setup_redroid14-data/_data/system/packages.xml.bak

cp /var/lib/docker/volumes/local-setup_redroid14-data/_data/local/tmp/packages-edited.abx \
   /var/lib/docker/volumes/local-setup_redroid14-data/_data/system/packages.xml

chown 1000:1000 \
   /var/lib/docker/volumes/local-setup_redroid14-data/_data/system/packages.xml
chmod 0660 \
   /var/lib/docker/volumes/local-setup_redroid14-data/_data/system/packages.xml
sync
```

Then perform the complete WSL/ReDroid reboot from section 8.3.

If Android fails to boot, stop the container and restore `packages.xml.bak` immediately.

Verify after boot:

```powershell
adb -s 127.0.0.1:5555 shell dumpsys package com.diskwalaapp |
  findstr /I "installerPackageName initiatingPackageName packageSource codePath flags"
```

Expected:

```text
codePath=/system/app/DiskWala
flags=[ SYSTEM HAS_CODE ALLOW_CLEAR_USER_DATA ]
installerPackageName=com.android.vending
initiatingPackageName=com.android.vending
packageSource=1
```

This corrects Package Manager metadata. It does not turn the operation into a genuine Play Store network transaction.

