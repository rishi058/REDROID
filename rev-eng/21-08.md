# 2026-08-21 - Diskwala PairIP / LSPosed runtime incident

## Summary

Diskwala was stuck at its splash screen and then moved control to Google Play / Play Store. The visible symptom looked like a PairIP licensing failure. Live logs confirmed that was correct: Diskwala started `com.pairip.licensecheck.LicenseActivity`, then called `System.exit(0)`, after which the app process died and Play Store remained active.

The PairIPFix and TalsecKill LSPosed modules were already installed, enabled, and scoped to `com.diskwalaapp`. The actual failure was lower in the stack: LSPosed's daemon process, `lspd`, was not running, so PairIPFix never loaded into Diskwala at runtime.

## Environment

- Host: Oracle VPS `ubuntu@141.148.151.172`
- Production container: `redroid14-kkssbzfd0c3sjec5nhs6g2mi`
- Android: ReDroid 14
- Kernel after reboot: `6.8.12-zksu-multi`
- Target package: `com.diskwalaapp`
- Diskwala installed version observed: `versionName=24.5`, `versionCode=334`
- Diskwala install metadata observed:
	- `installerPackageName=com.android.vending`
	- `initiatingPackageName=com.android.shell`
- LSPosed module packages:
	- PairIPFix: `io.github.ahmedmani.io.github.ahmedmani.pairipfixio.github.ahmedmani.pairipfix`
	- TalsecKill: `com.recon.talsecbypass`

## Standing Multi-Instance Rule Check

The concern was whether earlier work on `redroid-experimental` had crossed into production state.

Checks showed:

- Only production `redroid14-...` was present/running in `docker ps -a` at the time of repair.
- Production root/module state was under its own `/data/adb` bind mount.
- KernelSU modules were managed through `/data/adb/ksud`, not through the Manager GUI.
- No evidence from the incident pointed at a running experimental container or cross-instance module management.

The relevant rule still stands:

> Keep the KernelSU `su` allowlist empty, and manage modules per instance via `ksud` CLI rather than the Manager GUI.

TalsecKill currently masks this enough for runtime stability, but future fresh installs should preserve Play install metadata carefully.

### LSPosed DB state was correct

Android `sqlite3` crashed because of the existing hardened property/ICU issue, so the DB was copied out of the container and queried on the VPS host.

The DB showed PairIPFix and TalsecKill enabled and scoped correctly:

```text

5|1|com.recon.talsecbypass|/data/app/.../base.apk

5|com.diskwalaapp|0
2|com.diskwalaapp|0
```

So the bug was not a stale LSPosed scope row or stale module APK path.

### Zygisk / LSPosed runtime was broken

Before repair, KernelSU module metadata for Zygisk Next reported:

```text
[FAIL Stop zygisk due to crash, WARN 1 module(s) with issue: zygisk_lsposed, Root: OK KernelSU (33223), ZL]
```

LSPosed logs showed repeated daemon / zygote failures:

```text
Service::RequestLSPDex: transaction failed?
Read dex failed with 9: Bad file descriptor
JNI DETECTED ERROR IN APPLICATION: negative buffer capacity ...
/data/adb/modules/zygisk_lsposed/zygisk/arm64-v8a.so
```

After installing the local patched LSPosed tree, Zygisk recovered:

```text
[OK zygote, Root: OK KernelSU (33223), ZL]
```

But `lspd` still did not start because the installed module files had bad permissions.

### Immediate `lspd` service failure

Running KernelSU service scripts showed:

```text
sh: /data/adb/modules/zygisk_lsposed/daemon: can't execute: Permission denied
```

The installed module files had lost executable bits, for example:

```text
-rw-r--r-- root root /data/adb/modules/zygisk_lsposed/daemon
-rw-r--r-- root root /data/adb/modules/zygisk_lsposed/service.sh
-rw-r--r-- root root /data/adb/modules/zygisk_lsposed/bin/dex2oat64
```

This happened because the patched LSPosed folder was packaged on Windows with `Compress-Archive`; ZIP extraction through `ksud module install` did not preserve executable mode bits.

### Android toybox `unshare` incompatibility

The LSPosed service script originally used:

```sh
unshare --propagation slave -m sh -c "$MODDIR/daemon --system-server-max-retry=3 $@&"
```

On this Android userspace, `/system/bin/unshare` is toybox and rejects `--propagation`:

```text
unshare: Unknown option 'propagation' (see "unshare --help")
```

KernelSU's BusyBox does support that option:

```text
/data/adb/ksu/bin/busybox unshare --help
...
--propagation slave|shared|private|unchanged
```

## Root Cause

PairIPFix was not broken at the database/scoping level. It was not loading because LSPosed runtime was not active.

The two concrete causes were:

1. The installed LSPosed module was not the locally patched module tree expected by this ReDroid setup, causing Zygisk/LSPosed zygote failures.
2. Reinstalling the corrected tree via a Windows-created ZIP stripped executable permissions, so KernelSU could not execute `zygisk_lsposed/daemon` during service startup.

A secondary startup compatibility bug was that `service.sh` used Android toybox `unshare`, which does not support `--propagation`.

### 4. Fixed executable permissions in production

Applied inside the container:

```sh
cd /data/adb/modules/zygisk_lsposed
chmod 755 daemon service.sh action.sh \
	bin/dex2oat32 bin/dex2oat64 \
	bin/liboat_hook32.so bin/liboat_hook64.so
chmod 644 daemon.apk manager.apk framework/lspd.dex \
	zygisk/arm64-v8a.so zygisk/armeabi-v7a.so \
	module.prop sepolicy.rule uninstall.sh
```

### 5. Patched LSPosed `service.sh`

Updated local file:

```text
rev-eng/modules/zygisk_lsposed/service.sh
```

Important change:

```sh
MODDIR=$(dirname "$0")

cd "$MODDIR"

UNSHARE=/data/adb/ksu/bin/busybox
if [ -x "$UNSHARE" ]; then
	"$UNSHARE" unshare --propagation slave -m sh -c "$MODDIR/daemon --system-server-max-retry=3 $@&"
else
	"$MODDIR/daemon" --system-server-max-retry=3 "$@" &
fi
```

This avoids Android toybox `unshare` and keeps the script usable from full-path invocation.

### 6. Cleared stale Android proxy

Diskwala also logged network startup failures while Android global proxy pointed at `127.0.0.1:5556`.

Cleared with:

```sh
settings put global http_proxy :0
settings delete global global_http_proxy_host
settings delete global global_http_proxy_port
settings delete global global_http_proxy_exclusion_list
settings delete global global_proxy_pac_url
```

Final proxy state:

```text

```

## Notes / Cautions

- Do not manage modules through KernelSU Manager GUI while multiple rooted instances are in play.
- Do not rely on Android `sqlite3` for LSPosed DB inspection on this hardened image; copy the DB to the host and query with host `sqlite3`.
- Avoid packaging executable Android module trees with Windows `Compress-Archive` unless permissions are repaired after install.
- After a fresh Diskwala install, reapply and verify PairIPFix/TalsecKill scoping before launching.
- A full VPS reboot is the reliable activation boundary for KernelSU/Zygisk/LSPosed module changes in this deployment.
